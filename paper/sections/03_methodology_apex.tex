\section{Methodology: ARS Apex}
The "Apex" lineage focuses on maximizing data throughput by minimizing the total number of memory passes and leveraging hardware-level parallelism.

\subsection{The Fused Analyze Pass}
Traditional partitioning algorithms often require separate passes to find boundaries (min/max), check for existing order, and extract keys. ARS Apex implements a \textbf{Fused Analyze Pass} that performs all three operations in a single parallel traversal of the input array. This pass constructs a 64-bit spatial key cache and identifies sorted or reversed segments, allowing the algorithm to bypass binning entirely for low-entropy datasets.

\subsection{Lock-Free Parallel Prefix Sum Scatter}
To avoid the synchronization overhead of atomic counters, ARS uses a global prefix sum of thread-local histograms. Each thread calculates a local bin distribution for its assigned chunk and then uses the global offsets to write elements directly into a shared scratch buffer. This ensures that the partitioning phase is entirely lock-free and achieves 100\% utilization of available CPU cores.

\subsection{Hardware-Aware Block Buffering}
ARS Apex transforms random-access writes into sequential memory streams using \textbf{Block Buffering}. Elements are collected in stack-allocated L1-cache friendly blocks before being burst-copied to the global bins. This reduces cache thrashing during the scatter phase and improves L1 write-combining efficiency.
